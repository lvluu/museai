# muse-video

Every video generated through museai follows this skill. Paths below are relative to this skill folder (`.claude/skills/muse-video/`).

Nothing is delivered until `scripts/qa.py` says PASS and the contact sheet looks right (or the user accepts a named failure):
1. **Looks real** - photoreal people and place, no AI artifacts (morphing, extra fingers, warped objects, garbled text).
2. **Fluid motion + continuity** - consistent anatomy, faces, clothes, lighting, object positions. No jitter, stutter, frozen or duplicated frames, flicker, sudden pose changes, sliding. One continuous take by default.
3. **Natural conversation** - attentive listeners, replies at the right moment with brief pauses, no overlap, no awkward delays. Only the speaker's mouth moves.
4. **Lip sync + sound** - every syllable matches lips and jaw, no drift; spoken words = script; clean dialogue, no clipping, music quiet.
5. **One steady pace** - normal everyday speed for the whole video; never rushed, stretched or slowed to fit the clip.
6. **Readable captions** - large, bold, high contrast, outlined, synced, short phrases, never covering faces, mouths, gestures or key objects.

## Style block (automatic)
`scripts/muse-video` appends one style block to every prompt (set `QUALITY=0` only to debug). Edit these files to change the rules for all future videos; don't paste the rules into each prompt.
- `prompt/quality.txt` (default) - people talking: motion / continuity / conversation / lip-sync / speech pace / acting / caption-safe composition / final check. The model renders no text; captions are burned in afterwards.
- `prompt/travel.txt` (`STYLE=travel`) - travel documentary: real geography and landmarks, natural grade and light, slow plausible camera, instrumental music + ambience, no narration, no text on screen.

## Server
- museai FastAPI on 127.0.0.1:18610 (`uv run python -m museai` in the repo root, in a visible terminal tab). Check: `lsof -nP -iTCP:18610 -sTCP:LISTEN`; not listening → start it, wait for "Application startup complete".
- Every job failing within seconds with `cdp_connection_closed` (EP09 v7: twice in a row, no render) means the server's Chrome is gone: restart the server (stop it, `uv run python -m museai`, wait for "browser driver ready") and resubmit. A failed submit is not a take.
- Never print `data/api_key` or `data/accounts.json` (live muse.ai session cookies).
- `MUSE2API_VIDEO_TIMEOUT=1500` in `.env` (30-40 s videos take >10 min).
- Results also land in `data/media/vid_*.mp4`; copy each raw render into the working folder right away.
- Each account renders one video at a time; with N enabled accounts, N videos render in parallel. Extra requests queue for the next free account (`MUSE2API_MEDIA_QUEUE_TIMEOUT`, default 0 = no limit), so independent videos can be submitted at once. Sending the same prompt (and first frame) again while it is still queued or running returns the same task, not a second render: submit each clip once and wait for it. One agent session renders one video at a time (`scripts/muse-video` sends `X-Muse-Session`, default `$CLAUDE_CODE_SESSION_ID`): a session's extra requests queue behind its running one, so 4 sessions get 4 accounts and one session never takes them all. Clips of one multi-clip video still render in order (each needs the previous last frame).
- Add an account: export cookies from a logged-in https://muse.ai tab (Cookie-Editor JSON), then `uv run python scripts/import_account.py <export.json> --label muse-N` in the repo root (keeps only session cookies, checks the session). Delete the export afterwards. Every account is premium; never take one out of video jobs because of a bad render without proof.

## Before rendering: fit the script to the clip
`python3 scripts/budget.py script.txt <duration>` (a file with the dialogue lines only; run on the full prompt it counts every line and overshoots) - needs ≤ duration and ≥ 75 % of it at 4.5 syllables/s. TOO LONG → shorten the script (keep the meaning) or extend the clip. TOO SHORT → add a natural line or shorten the clip (an under-filled clip gets padded with silent pauses). The total video length is not a target: it follows the dialogue at a natural pace. Never ask the model to speed up or slow down instead. Split lines over 14 syllables.

## Generate one clip
```
SIZE=9:16 DURATION=40 OUT_NAME=clip.mp4 NO_OPEN=1 scripts/muse-video -f prompt.txt
```
Output in `~/Movies/museai/`. The video length comes from the prompt: always set `DURATION`, and the script adds an OUTPUT line asking for exactly that many seconds in 4K UHD (2160x3840 for 9:16), falling back to full HD 1080p. It prints the delivered length and size and never rejects or blocks a render. `IMAGE=first.png` sets the first frame. A busy account (`no_account_available`), a server restart (`interrupted`) or a down server are retried automatically (`RETRIES=15`, `RETRY_WAIT=120` s), so one call yields one finished video; run it in the background and don't resubmit by hand. If muse replies with text only (`upstream_refused`), prepend "NEW STANDALONE REQUEST. Ignore any earlier versions, drafts or projects. Generate one new video from scratch and return the finished video file in this reply. Do not reply with text only." and retry.

## Prompt (per video; the quality block is added for you)
EVERYDAY CHINESE briefs: the user's format, the episode log and the rules for drafting the next episode are in `prompt/everyday-chinese.md`; add each new episode to its log.
Sections: CAST, SETTING, VOICE, CAMERA, SCRIPT.
- **CAST**: age, ethnicity, hair, exact outfit colours, voice type per person. "Keep faces, hairstyles, outfits, props and voices identical for the whole video."
- **SETTING**: one real, specific place with a few concrete objects that stay where they are.
- **VOICE**: language + accent, e.g. "Natural Standard Mandarin (Putonghua), accurate tones, warm everyday intonation, about 4.5 syllables per second for every line." Optional "very quiet instrumental music far below the dialogue", or none.
- **CAMERA**: default "One continuous take, steady locked camera, medium two-shot framed from the waist up, both bodies face the camera squarely, each person turns only the head partway toward the other (front three-quarter view, both eyes and the whole mouth visible, never side profile), faces large in the upper half of the frame." "Angled about 45 degrees toward the camera" still came back with the man in profile in 4 of 4 EP10 takes; "bodies face the camera squarely, turn only the head partway" held three-quarter faces and passed a face-mesh lip check on the first take. Knees-up framing with the man nearly in profile gave EP10 weak, mumbled lips and a listener whose smile read as talking (a face-mesh lip check failed 4 of 11 lines). Add a cut only if the user asks; give its time and what carries over.
- **Intro shot + cut** (e.g. a to-camera intro, then the two-shot): muse redraws the person after the cut and has aged or swapped faces (EP07: 40-year-old in the intro, 25-year-old at the desk). Pass `IMAGE=` a 9:16 still of that person (crop a frame of an earlier episode or render) and write "The woman in the attached image is the same woman in every shot: identical face, age, hairstyle and outfit."
- **Turn to camera at the end**: write "she turns her head and starts speaking within 0.3 s"; otherwise the turn adds a >1 s silent gap that fails the pace check. muse often ignores this and the "listener never looks at camera" rule (EP09: 6 of 6 takes had a 2-2.5 s pause before the turn and the man turned to camera too, three-quarter phrasing included). Plan the post fix below instead of a 4th re-render. What held the listener (EP10 v4 last clip, take 2 after take 1 failed): "The man stays in profile facing the woman for the whole clip; only the woman ever faces the camera." next to the "never looks at the lens" rule.
- **Faces toward the camera need a first frame**: the CAMERA text alone did not hold it (EP10 clip 2: "45 degrees, three-quarter, never profile" still came back in profile, and an `IMAGE=` of the woman alone made the camera drift to find the man). What worked: generate the two-shot still first, then render with `IMAGE=` it and "The attached image is the exact first frame: keep both faces, angles, framing and camera position." Still: `POST /v1/images/generations` with `{"prompt": ..., "n": 2, "size": "1080x1920", "response_format": "b64_json"}` (same CAST/SETTING text + "both bodies and faces angled about 45 degrees toward the camera, front three-quarter view, NOT side profile, framed from just below the waist up, mouths closed"), pick the one whose people match the earlier shots, scale to 1080x1920.
- **SCRIPT**: dialogue lines only, one per line with speaker label, in order.
- **Label every line with the speaker AND the listener's action**: `WOMAN speaks, in her female voice, only her lips move. The MAN listens: lips pressed together in a closed-mouth smile, jaw still, he does not mouth her words: ...` and the mirror for the man. A concrete listener action works better than "lips stay closed"; EP09 v4 took that wording and the man still mimed 2 of the woman's lines, the woman 2 of his. EP09 v6 (this wording plus the open stance) still failed all 4 takes of clip A, so plan the reframe fix in QA instead of re-rendering for a miming listener. In SETTING stage both people "in an open stance angled about 45 degrees toward the camera, turned only partly toward each other, so both faces are in clear three-quarter view and both mouths are fully visible in every frame; never strict profile". Facing each other puts one face in profile: muse then moves the visible mouth for both voices, and the mouth check cannot read a profile. In LIP SYNC add "Turn-taking: one mouth at a time. The speaker's lips close at the end of the line before the other person's lips open."
- **Never film a speaker from behind** (over-the-shoulder, back of head, both facing a counter): muse then gives that speaker's lines to the visible listener's lips. EP08: woman filmed from behind at a ticket counter → the clerk mouthed all 5 of her lines with a female voice. Use a side-on two-shot where both mouths stay visible; a later clip that turns one person to camera keeps the other in profile, silent.

## Short renders
muse has returned 10 s 720x1280 clips for 30 s requests (2026-10-26), on muse pro accounts, while replying "Generating your 30-second video". The OUTPUT line states the length and 1080p explicitly to steer it. If a clip still comes back short, tell the user the length and size the script printed; don't disable accounts for it. A first render that comes back 10 s with the whole script squeezed into it is unusable (rushed speech): switch to a multi-clip plan right away instead of retrying the single render (EP06: 30 s request -> 10 s clip with 8 of 12 lines).

## Multi-clip videos (continuity) - ALWAYS
The last frame of clip N-1 is the first frame of clip N.
1. **Plan in 10 s clips.** Split the script so each clip holds 7-8 s of speech (30-36 syllables, about 4 short lines, `budget.py part.txt 8` must say OK, not TOO SHORT), and each clip's prompt says `PART n of N`, 10 seconds, its own lines only. Put an intro cut in clip 1 and a turn to camera in the last clip. Render with `DURATION=10`. An under-filled clip gets padded with silence whatever the TIMING text says (EP09 clip 3: 21 syllables in 10 s -> 1 s lead-in + 2.3 s pause in every take; clip 1 with 3 lines had a 3.5 s silent tail). Move lines between clips until every clip is full, the last clip included.
   **Submit each clip once** (one request, one account). If it fails its check, re-render it once, one request at a time; never render parallel takes of the same clip. `muse-video` sends `X-Muse-Session` (`MUSE_SESSION`, default `$CLAUDE_CODE_SESSION_ID`), so the server runs one render per session at a time and queues the rest.
2. Render clip 1 normally; render every next clip with `CONTINUE_FROM=<previous clip>` (grabs its last frame as the first frame and prepends a CONTINUITY instruction).
3. Same cast, outfits, setting, lighting, camera position, action and gaze as the previous clip's ending. End each clip on a calm resting pose.
4. **Check every clip before chaining**: `scripts/check_clip.sh clip.mp4 [previous.mp4]` (cuts, transcript, sheet with the seam), then `pron.py` on the clip with its own cues (below). Re-render the clip, before rendering the next one, if it has a cut you did not ask for, a person outside the cast (EP06: a shopper walked in behind them in the last 0.8 s, together with a second cut), words not in the script (EP06: the assistant answered the ending question with 合身的), the listener turning to the camera with the speaker, or any `jumps:` line (a one-frame snap of pose/face inside the clip; EP09 v7 clip B snapped 6 times and the user saw the glitches; aligning the frames left a diff of 7-10, so no post fix hides it). Add `SCRIPT=script.txt` ("W: line" per line) so it also runs the speakers check on the clip: `WRONG VOICE` means re-render; `LISTENER MOUTH MOVES` does not need a re-render (the reframe step fixes those lines in post). Everything after a bad clip has to be re-rendered, so catch it here.
5. **Trim silence at the seams** (cutting the ends of a clip does not retime anything, so lip sync is kept): cut each clip about 0.4 s after its last syllable *before* using it as `CONTINUE_FROM` (EP06 clip 1 had 2 s of music-only tail), and cut a continued clip's silent lead-in (EP06 clip 3 started speaking at 2.5 s). The lead-in often drifts or zooms slightly, so cut as little as needed and check the seam again. `ffmpeg -t <end> -c:v libx264 -crf 16 ...` / `ffmpeg -ss <start> ...`.
6. **Fix cuts and pauses in post when re-renders keep failing** (`scripts/cutedit.py plan.json out.mp4`, segments of the clips joined with hard cuts; nothing is retimed):
   - Intro cut missing (EP09: 3 of 4 clip-1 takes stayed in the two-shot, man half in the intro): cut from the intro clip to the two-shot clip *inside the pause after the intro line*, which also drops that pause. Never punch in (crop) on one face: the user wants one steady medium two-shot, no close-ups, zooms or punch-ins (EP10 v3 used punch-ins on a miming listener and was rejected).
   - Listener turns to camera at the ending, or a long pause before the last line: re-render that clip, or cut inside the pause to the same two-shot framing from another take.
   - Pauses inside one continuous take cannot be cut without a jump: re-render that clip or name the failure.
   - Find cut points with `python3 scripts/gaps.py video.mp4` (energy-based speech spans and gaps).
   - Trimmed pauses shorten the video: if it falls under 30 s, add a natural line (needs the user's OK when the brief fixes the script) rather than leaving pauses in.
7. Join with `scripts/stitch.sh out.mp4 part1.mp4 part2.mp4 ...`: denoises each clip (`afftdn`; EP10 clips 2-4 came back with a white hiss floor at -51 dB above 7 kHz, which loudness matching raised to an audible -46 dB; the clean clip sat at -86 dB), drops the duplicate first frame and cuts each clip's audio to its kept frames (EP10: trimmed clips carry up to 25 ms more audio than video, and the dropped frame's audio stayed in; both pushed later clips' voices off their lips and left the join at 23.8 fps), scales every clip to the first one's size (muse returned clip 2 of a 1080p chain at 720x1280), and evens out loudness between clips (EP06 clips came back 8 dB apart). **Ease the seams first, always**: continued clips start reframed (EP09 v7: 3.7-4.2 % zoom and ~10 px shift at both seams, YDIF 17 vs ~0.6 per frame; the user saw it as an AI glitch). `uv run --no-project --python 3.12 --with opencv-python-headless==4.10.0.84 python scripts/ease_seams.py eased part1.mp4 part2.mp4 ...` measures each seam and spreads the reframe over 1.5 s (`EASE`) as a slow camera move on the tighter side, nothing retimed, so it works over speech (EP09: frame diff 20 → 2-3 at both seams). Stitch the eased clips: `scripts/stitch.sh out.mp4 eased/part1.mp4 eased/part2.mp4 ...`; `python3 scripts/jumps.py out.mp4` must say `RESULT ok` (qa's smooth check fails on any jump left). `XFADE=0.25` in stitch.sh is only for a seam that is a real change of shot, never over speech. Then shorten long pauses: `python3 scripts/shorten_pauses.py stitched.mp4 tight.mp4` cuts every pause > 1.0 s down to ~0.45 s inside the silence with a 0.2 s dissolve (EP08: five 1-2 s pauses, 27.9 → 22.3 s, no syllable moved). Subtitle and QA the result.
8. **Dub the stitched file (every multi-clip dialogue video; qa.py's `voices` check fails without it)**: EP09 v7 skipped this step, passed every other check, and the user heard both characters' voices change between lines (voices.py: same-speaker similarity 0.51-0.68 raw, 0.74-0.84 dubbed). each muse render picks its own voices, so a person's voice, timbre and accent change at every seam (EP08: the woman 183-258 Hz across 4 clips, the clerk a different man each clip). Prompting the same voice does not hold it. Build cues.json first (step 2 below), then `uv run --no-project --python 3.12 --with edge-tts --with librosa --with soundfile python scripts/dub.py stitched.mp4 cues.json WMWM... dubbed.mp4`: one fixed standard-Putonghua neural voice per person (`VOICE_W` zh-CN-XiaoxiaoNeural, `VOICE_M` zh-CN-YunjianNeural; zh-CN-YunxiNeural measured 160-210 Hz and failed as male, zh-CN-YunyangNeural sounded too old and formal for a 27-year-old clerk), each line starting on the original lips (split at commas where the original pauses) and playing at the voice's own speed, running on into the following silence when the lips were faster. Never time-stretch or push the voice past +20 % (EP08: +40 % plus a phase-vocoder stretch sounded pitched and unnatural to the user). It prints each part's voice length vs the lip span; `OVERRUN` means it runs into the next part or speaker. It also writes `dubbed.cues.json`, the cues retimed to the new voice: burn captions and run qa.py / speakers.py with that file, not the lip-timed cues (those end with the lips, so captions vanish early and qa reads a normal-speed voice as too fast). The voice is never pitch-shifted, slowed or time-stretched, and `MAX_PCT` cannot go above 20. Single-clip videos keep muse's own voice. Run speakers.py on the dubbed file: any `SOUND WITHOUT LIPS` line → the dub's voice outruns the lips there; keep muse's own audio for the video instead (EP09 v5: dub FAIL lines 4, 13; muse audio passed line 13). Lip sync beats one constant voice.
   **Pace off after dubbing**: the TTS pauses at every mark inside a line and shouts on "！". Copy cues.json, edit only the off line's text for the TTS (drop the mark where the lips do not pause; "！" → "。" on a short exclamation), dub with the copy, and keep the original text for captions, pron.py and qa.py (EP10: 当然可以！用你的手机吗 3.7 syl/s → 4.8 without "！"; 对，麻烦你了 3.8 → 4.5; YunjianNeural's 可以！ at 242 Hz failed as male, 可以 at 152 Hz). Do not strip marks on every line: the lines then ran ahead of the lips (0.73x) and left gaps over 1 s.
   **Leave room for the voice when planning**: muse's lips run faster than a natural voice (EP08: the dubbed lines ran 0.2-0.45 s past the lips), so in each clip's timeline put ≥ 0.5 s between one line's end and the next speaker's start.

## Timing, QA, captions
1. **Word timings**: `WMODEL=medium uv run --no-project --python 3.12 --with faster-whisper --with opencc-python-reimplemented python scripts/transcribe.py video.mp4 words.json` (no hint first: the script hint can make Whisper skip or invent lines; add it only if words are misheard). Word starts absorb leading silence, so tighten cue bounds with `scripts/gaps.py` (energy-based) before judging pace. Missed lines → cut that span to wav and rerun with `VAD=0`.
2. **cues.json**: `[[speech_start, speech_end, line1, line2, ...], ...]` from the word timings (EVERYDAY CHINESE: zh, pinyin, vi). One short, meaningful phrase per cue.
3. **QA gate** (on the video before captions; each caption change counts as a picture jump): `SPEAKERS=WWMW... python3 scripts/qa.py video.mp4 cues.json words.json [planned_cuts=0] sheet.jpg`
   - format 1080x1920 (or 4K 2160x3840), constant 24–30 fps (length is not checked)
   - voice: transcript vs script ≥ 90 %
   - sound: peak < -0.5 dB, mean > -30 dB
   - noise: hiss floor above 7 kHz < -70 dB (only voices + music; `stitch.sh` denoises, a raw clip that fails is fine once stitched)
   - pace: every line 3.8–5.5 syllables/s, fastest ÷ slowest ≤ 1.35, no pause > 1.0 s
   - smooth: no freeze ≥ 0.5 s, ≤ 5 % repeated frames, hard cuts == planned, no one-frame picture jump (`jumps.py`: YDIF > 3, > 5x the frames around it). A jump at a seam → `ease_seams.py` (step 7); inside a clip → re-render that clip.
   - voices: `SPEAKERS` (one letter per cue) is required; `voices.py` embeds every line (resemblyzer) and fails a line whose median similarity to the same speaker's other lines is < 0.70 (`VOICE DRIFT`). Fix with `dub.py` (step 8), not a re-render: each muse render picks new voices. Pitch is no identity check (dubbed woman 226-293 Hz per line). Standalone: `uv run --no-project --python 3.11 --with resemblyzer --with librosa --with setuptools python scripts/voices.py video.mp4 cues.json WWMW...`.
   - speakers (every dialogue video): `uv run --no-project --python 3.12 --with mediapipe==0.10.14 --with opencv-python-headless==4.10.0.84 --with librosa python scripts/speakers.py video.mp4 cues.json WWMW... mouths.jpg` (one letter per cue; `LEFT=W` = who stands on screen left). Fully automatic, exit 1 on a failed line: `WRONG VOICE` when the line's median pitch does not fit the speaker (female > 165 Hz; EP09 take a3: the woman's 你今晚有空吗 in a male voice), `LISTENER MOUTH MOVES` when the listener's lip gap (face mesh on an upscaled crop of each face, every frame) has std > 0.010 and frame-to-frame change > 0.004 (EP09 v4: closed listener std <= 0.004, the man miming std 0.016-0.022). Lines showing `no listener face` were not checked (profile or punch-in): look at those columns in mouths.jpg. `SPEAKER FACE HIDDEN` when the speaker's face (frontal or profile, or alone as a punch-in) is found in < 50 % of the line (EP08: woman filmed from behind, the clerk mouthed her lines, face seen 0 %; opencv 5 ships no haar cascades, so keep the pin). `WRONG VOICE` or `SPEAKER FACE HIDDEN` → re-render that clip. `LISTENER MOUTH MOVES` → re-render that clip with the listener rule quoted for that line (the steady two-shot stays; never hide the listener with a punch-in, see step 6). Look at the mouth sheet column of every `no listener face` line too. A flag just over the limit (move <= 0.0045, lips closed on the sheet) on a single clip can pass on the dubbed cues, which end with the new voice (EP10 v4 clip 3: 0.0042 raw, ok after dubbing), so decide that line on the dubbed run before re-rendering. A line spoken with the other person's voice and still lips is not fixed by asking for "clearly articulating" lips: EP10 v4 last clip came back with both smiling open-mouthed; keep the better take and dub it. Never deliver with a miming listener on screen. Eyeballing the mouth strips missed this twice in EP09, so the numbers decide. Two-shot faces measure up to 0.46 of the frame width; only a single face wider than 0.55 counts as a punch-in. `SOUND WITHOUT LIPS (x s)` when the voice is loud (> -32 dB) for ≥ 0.45 s while the speaker's lip gap stays within 0.012 (EP09 v5, reported by the user: muse moved the man's lips for the woman's 一起去吃饭吧 while hers stayed frozen, and the reframe to her close-up showed a voice over still lips; dubbed tails ran 0.54 s past closed lips). A line with both `LISTENER MOUTH MOVES` and `SOUND WITHOUT LIPS` is a wrong-lip line, not a mime: reframing exposes it, so re-render that clip.
   - contact sheet: every tile real, same faces/outfits/background, normal hands
   - **pronunciation** (Mandarin): qa.py runs this itself and fails `pron` on any wrong syllable; never deliver with it failing. EP09 v6 shipped with 地铁 said as 铁铁 and 吃饭 as 区方 (the user heard both) because pron.py was a separate step that got skipped, while qa's voice match still said 96 %. Run it per clip too, before chaining, so a bad clip is re-rendered before the next one starts from it. Standalone: `uv run --no-project --python 3.12 --with faster-whisper --with pypinyin --with opencc-python-reimplemented python scripts/pron.py video.mp4 cues.json` transcribes each line on its own and compares toned pinyin with the script; any missing or changed syllable/tone fails (a homophone with the same tones passes, 了→啦 particle swaps pass). Uses Whisper large-v3; medium flagged correct lines. A line that fails in a clip can often be moved to the next clip instead of re-rendering the whole clip (EP10: 竖 said as 收 in the last line of clip 2; clip 2 was cut after line 3 and the line opened clip 3).
   - FAIL → re-render with the failing rule quoted more strongly in the prompt. Never retime audio in post (breaks lip sync). Pauses over 1 s: `scripts/shorten_pauses.py` (cuts inside the silence only). After 2 failed re-renders, deliver the best one and name the failed checks.
4. **Burn captions**: `uv run --no-project --python 3.12 --with pillow python scripts/burn_subs.py video.mp4 cues.json out.mp4`
   - Large bold white text, thick dark outline. Chinese 112 px, Latin 66 px.
   - Single-language video: at most two lines on screen. EVERYDAY CHINESE: one line per language (zh / pinyin / vi), each kept to one row by short cues.
   - Box x6–84 %, y57–75 %, block centred near 66 %; bottom 25 % and right-side buttons stay clear. Fixed position, no bouncing or flashing. Shown 0.15 s before speech, until 0.7 s after or the next cue.
5. **Verify** frame grabs with captions at several cue times: text inside the box, no face, mouth, gesture or key object covered. Then deliver.
6. **Deliver in two steps, 4K last**:
   - **Preview**: `scripts/deliver.sh final.mp4 <work_dir> [prefix]` copies the QA-passed 1080p video to `~/Desktop` (the user wants it there) and keeps the work folder, so fixes start from the parts at hand. Run it only after QA PASS and the frame check, and ask the user to review it.
   - **Final**: only after the user accepts the preview (says it is final/ok, no more fixes), `FINAL=1 scripts/deliver.sh final.mp4 <work_dir> [prefix]` (in the background) overwrites the Desktop copy with the 4K UHD version, checks it, then moves the work folder (raw clips, sheets, mouth strips, frame grabs, cues, prompts) and the `~/Movies/museai/<prefix>*` renders to the Trash, so only the Desktop video is left. Keep one work folder per video (e.g. `~/Work/ep10`) so this removes nothing else; it refuses home, repo and Desktop folders. Never run the 4K step before the video is final: the user asked for 4K only after finalising (2026-10-27), it takes ~1 h for 15 s and every fix would throw it away.
   **4K delivery (always)**: the user wants every video in 4K UHD. muse returned 1080x1920 for a 15 s travel render (Plitvice, 2026-10-27), so the final `deliver.sh` runs `scripts/upscale.sh`: 2160x3840 for 9:16, 3840x2160 for 16:9, same frames and untouched audio, so lip sync and burned captions stay put. A lanczos resize alone looked "a bit vague" to the user (Positano, 2026-10-27), so upscale.sh runs Real-ESRGAN (realesrgan-x4plus, quarter-size frames enlarged 4x, then a temporal-only denoise against shimmer; ~10 s per frame on an M1 Pro, ~1 h for 15 s: run the final delivery in the background). It needs the ncnn-vulkan build in `~/Work/tools/realesrgan` (`gh release download v0.2.5.0 --repo xinntao/Real-ESRGAN -p '*macos.zip'`, unzip there; a download that drops partway can simply be rerun); without it upscale.sh warns and falls back to lanczos. Run QA and burn captions on the 1080p file, upscale only at the final delivery. The 4K detail is AI-generated from the 1080p render: say so on delivery. `UHD=0` keeps the rendered size, `ESRGAN=0` forces lanczos.
   **Sharp first frame**: muse renders from `IMAGE=` as given; a 576 px-wide crop stretched to 1080x1920 gave a soft video. Crop from the largest source available, or upscale a small reference with Real-ESRGAN before rendering.
7. **Clean up**: right after the final delivery, leave nothing else behind. Remove every git worktree made for this video (`git worktree remove <path>`, after its PR is merged or its changes are committed and pushed), delete its merged local branch, and trash stray files the work left in the repo or home (scratch scripts, prompt/script text files, `ep*` folders, extra Desktop copies). ## Fixing a delivered video
When the user reports a problem (wrong word, miming listener, bad seam, caption, sound), fix only the broken part and rebuild; never re-render the whole video for a local problem.
1. **Update the skill first** (see "Maintaining this skill"): add the rule, prompt wording or check (prefer a `qa.py` / `check_clip.sh` gate over a sentence) that would have caught it, so the next video does not repeat it.
2. **Get the parts back**: before the final delivery the work folder is still in place; after it, restore it from `~/.Trash` (the final deliver.sh put it there; the agent may lack Trash access, so ask the user to put it back). Find the broken span: which clip, which line, which seconds.
3. **Fix the smallest unit**, cheapest first:
   - post only, no render: captions (rerun `burn_subs.py` with fixed `cues.json`), pauses (`shorten_pauses.py`), a cut or reframe (`cutedit.py`), loudness or seams (`stitch.sh`, `ease_seams.py`);
   - one line wrong: move or cut it at a clip boundary (see pronunciation above) before re-rendering anything;
   - one clip unusable: re-render only that clip with `CONTINUE_FROM` the clip before it. Keep the clips after it: trim the new clip's tail to a resting pose and smooth the join to the next clip with `ease_seams.py`; re-render a later clip only if `jumps.py` still fails at that seam.
4. **Rebuild**: `stitch.sh` with the kept + fixed clips, burn captions, run `qa.py` and the frame check, then `deliver.sh` (preview again; 4K only once the user accepts) and clean up after the final one. Tell the user which part changed.

## Travel videos (`STYLE=travel`)
Real destination, no dialogue, no captions. Rules 3-6 above don't apply; rules 1-2 do.
1. **Prompt** sections: PLACE, TIME + WEATHER, SHOTS, MUSIC.
   - **PLACE**: real named location + the concrete landmarks/terrain actually there (e.g. "Ha Long Bay, Vietnam: limestone karsts rising from emerald water, wooden junk boats"). Never ask for things that are not there.
   - **TIME + WEATHER**: one time of day and weather for the whole clip (e.g. "early morning, light mist, soft low sun from the left").
   - **SHOTS**: default one continuous shot with one slow move (drone push-in, slow pan, gentle dolly). Multiple shots only if asked; list them in order with the move per shot.
   - **MUSIC**: instrument + mood matching the place (e.g. "soft đàn bầu and strings, calm"), plus the ambience (waves, birds, wind).
2. **Render**: `STYLE=travel SIZE=16:9 DURATION=10 OUT_NAME=place.mp4 NO_OPEN=1 scripts/muse-video -f prompt.txt` (`SIZE=9:16` for shorts). Longer → multi-clip with `CONTINUE_FROM`, same as above.
   - **Asked for more than 10 s, muse may join its own clips**: a 15 s Lauterbrunnen request (2026-10-26) came back 15 s 1080x1920, but at 10.04 s it cut back to ground level with different light (qa: `cuts at [10.04]`). Keep the good part up to the cut (`ffmpeg -t <cut>`) and render the rest as a `CONTINUE_FROM` clip instead of re-rendering the whole video.
     The join can also be a dissolve that qa does not see: a 15 s Positano image-to-video (2026-10-27, `IMAGE=` first frame) dissolved at 5.75-6.5 s into another view (tiled dome turned plain grey, calm blue sea turned turquoise with whitecaps, framing lower) and qa said `cuts at []`, PASS. Look for this on the contact sheet of every render over 10 s; keep the part before the dissolve and continue from it the same way.
   - **A continued clip pans away unless the camera is locked**: Positano part 2 with "almost imperceptible sideways drift, slowing, then still" panned right and down from ~4 s until the dome left the frame. The re-render with "LOCKED-OFF CAMERA ON A HEAVY TRIPOD FOR ALL 10 SECONDS ... does not pan, tilt, slide, drift, push in, pull out or zoom ... every building stays at exactly the same pixel position and size ... only nature moves" held the frame for all 10 s. Use the locked wording for every continued travel clip; any drift the brief wants already happens in the first clip.
   - **Two renders bring two music takes**: `stitch.sh` joins audio hard, so the music jumps at the seam. When the first clip was cut out of a longer render, crossfade its own audio past the cut into the next clip's audio (0.8 s `afade` out/in + `amix`, then `loudnorm`) and keep the stitched video stream (`-c:v copy`).
   - **Continued clips start reframed**: the first frame of a `CONTINUE_FROM` clip is slightly shifted and zoomed against the given frame, so the join jumps for one frame (frame difference 14 vs ~5 elsewhere, below the hard-cut threshold, so qa still passes). A re-render with "first frame pixel-identical, no reframing" jumped the same. Run `scripts/ease_seams.py` on the clips before `stitch.sh` (multi-clip step 7): it turns the reframe into a 1.5 s slow camera move, keeps every frame, and works for dialogue too (a crossfade over speech would blend two mouths). `jumps.py` on the joined file must say `RESULT ok`.
   - **"No zoom" still gets a push-in**: asked for a near-static lateral glide with "no zooms, no change in shot size, 2-3 m travel", a 15 s Lake Bled render (2026-10-26) pushed in over the first ~7 s (island ~2x bigger, foreground reeds left the frame), then held; qa passes this, so judge shot size on the contact sheet. Adding "slider at water level, constant focal length, never moves forward or backward, never zooms, the island stays exactly the same size in every frame, foreground trees and reeds stay in frame" halved it (island ~1.5x, reeds kept) but did not remove it. Use that wording from the first render, and tell the user about any push-in left.
3. **QA**: `python3 scripts/qa.py video.mp4 --travel [planned_cuts=0] sheet.jpg` - format 1920x1080 or 1080x1920 (or their 4K sizes), 24-30 fps; no clipping, mean > -35 dB; smooth as above. Contact sheet (12 even frames): real place, no invented landmarks, warped buildings, repeated mountains, HDR halos, text or watermarks; same light and weather throughout. FAIL → re-render with the failing rule quoted more strongly.
4. No captions, no burn step. After PASS + sheet check, preview with `scripts/deliver.sh`; 4K (`FINAL=1`) only once the user accepts it.

## Maintaining this skill
Agents update this skill directly, without asking, whenever a render, QA run or user correction teaches something new: fix the rule here, in `prompt/*.txt` or in `scripts/`, then run the whole flow on autopilot, never asking the user:
1. Branch from the latest `origin/main` (`git fetch origin main`), commit, push the branch, `gh pr create`.
2. Before merging, `git fetch origin main` again; if the PR is `CONFLICTING`/`DIRTY`, rebase onto `origin/main`, resolve keeping both sides' rules (main's newer text plus this change), check scripts (`bash -n`, `python3 -m py_compile`), `git push --force-with-lease`.
3. `gh pr merge <n> --squash --delete-branch` once it is `MERGEABLE`, then switch the checkout back to the updated main and delete the local branch.
Name the base branch only through `origin/main` refs or `gh` defaults: a hook blocks any command that looks like a push to main (e.g. `gh pr create --base main` in the same command as `git push`), so run push, PR create and merge as separate commands.
 The skill lives only in this repo; never copy it to `~/.claude/skills/` or another folder. Record only lessons proven by a render, not guesses.
